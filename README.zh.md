# dsh-task-toast

> 面向 [DeepSeek Harness](https://www.deepseek.com/harness/)（DSH）的跨平台任务通知插件。

[English documentation](README.md)

任务完成时，通过 Windows 或 macOS 系统通知提醒你。通知可带简短结果摘要，点击后打开产生任务的会话；如果系统通知不可用，插件会在 DSH 内显示提示。完整结果始终保留在会话中。

## 维护状态

截至 2026-11-21，本项目已完成预期功能，停止主动功能迭代。保留当前可安装代码和完整使用说明，仅在真实故障、DSH 兼容变化或明确的交互障碍出现时恢复维护。

## 功能

- **跨平台系统通知**：Windows 和 macOS 共用 DSH 客户端的 Web Notifications API。
- **任务结果预览**：系统通知正文最多 240 个字符（含完成提示和摘要）；点击通知跳转到来源会话查看完整内容。Windows 桌面版会先恢复最小化或隐藏在托盘中的 DSH 窗口，再打开对应会话。
- **应用内提示**：提供「查看结果」「稍后」「忽略」操作，并支持查看和重播近期通知。
- **可选提示音**：轻柔、清晰两种音效；默认关闭，可试听或一键关闭。
- **前台感知**：正在查看且仍在运行的会话不弹通知，只记入历史；其他会话仍可提醒。
- **可配置界面**：简体中文 / English、主题、位置和自动消失时间。
- **市场托管更新**：统一通过 dshmarket 管理发行版本；插件不再自行覆盖安装文件或执行包管理命令。
- **多类任务事件**：覆盖子代理、工作流、后台任务和顶层会话的完成状态。

## 安装与更新

本仓库提供当前可安装源码与预构建产物；插件市场渠道仅考虑 dshmarket。更新仓库与获得市场收录是两个步骤。

### DSH 桌面应用

打开 **插件 → 添加插件 → 安装第三方插件**，输入下方仓库地址，安装后启用：

```text
https://github.com/LouieKeung-13/dsh-task-toast
```

替换已有安装时，先在桌面应用中卸载旧副本，再从该地址安装。首次迁移需要安装完成后完整重启，原因见下文；在换包之前重启仍然加载旧版。

### DSH Web profile

```sh
dsh plugin --profile web add github:LouieKeung-13/dsh-task-toast
```

桌面 profile 由桌面应用管理，安装请使用其插件管理界面。

### 通过 dshmarket 更新

- 目录收录本仓库后，可进入 **插件 → 插件市场 → 已安装** 检查和执行更新。市场自动检查只提醒，不会静默安装；本地测试包也不会自动切换为市场安装源。
- 通知设置中的 **打开插件页** 会打开宿主插件页面，再进入插件市场即可管理更新。
- 更新后按宿主实际结果处理：直接生效、刷新页面或需要重启。仅文件替换成功不能证明新代码已经运行。

从未释放 HTTP 路由的旧版首次迁移到本次修复版，需要完整重启 DSH 一次。后续替换可正确卸载和重新挂载插件，避免保留旧路由；同进程内保留设置、通知队列和投递游标，不新增跨应用退出的配置持久化。

## 快速开始

1. 打开 **设置 → 任务提示** 并启用插件。
2. 将 **任务完成** 设为 **系统通知**。全新安装默认使用此设置；支持的同 Host 进程重载会保留设置，完整重启后请重新核对通知偏好。
3. 如系统询问权限，请允许通知。横幅和通知中心是否显示由操作系统设置决定。
4. 保持 **显示结果摘要** 开启，可在系统通知正文（最多 240 个字符）中看到任务结果的简短预览。关闭摘要时横幅仍显示完成标题，但不会显示结果正文。点击通知后可在来源会话中查看完整内容。
5. 可在 **任务完成音效** 中选择「轻柔」或「清晰」并试听。默认关闭。

**发送测试通知**用于检查通知投递。测试通知会关联发送时选中的会话，但不包含真实任务结果。要完整验收摘要和回跳，请完成一个真实后台任务。

## 通知行为

| 方式 | 行为 |
| --- | --- |
| **系统通知** | 发送一条操作系统通知。权限被拒、接口不可用或投递失败时，回退为一条应用内提示；投递成功时不会再重复弹应用内气泡。 |
| **应用内提示** | 在 DSH 内显示通知，可使用「查看结果」「稍后」「忽略」操作。 |
| **关闭** | 关闭对应通知类别。 |
| **显示结果摘要** | 从最新已回答的用户回合提取助手普通文本。不会显示 reasoning、工具调用 / 工具结果或旧回合答案；关闭摘要时系统横幅只显示完成提示，无可用答案时保留通用完成正文。 |
| **任务完成音效** | 「关闭」「轻柔」「清晰」。音效在客户端本地合成，不下载音频文件。 |

系统通知只显示简短预览，不是完整对话。正文总长最多 240 个字符，包含本地化完成提示和结果摘要；只显示纯文本，不渲染 HTML 或执行结果内容。系统通知由操作系统控制，锁屏时也可能显示。任务内容敏感时，请关闭 **显示结果摘要**。通知显示名、横幅时长、系统声音和通知中心留存受 DSH、客户端运行环境及操作系统设置影响。插件需要 DSH 客户端运行才能收到任务事件。

当某个会话正在前台查看且仍在运行时，该会话的提醒只写入历史，不会在任务结束后自动补弹；其他会话的任务仍可提醒。

## 设置说明

- **任务完成 / 错误失败**：分别设置为关闭、应用内提示或系统通知。
- **「查看结果」行为**：应用内提示可跳转到来源会话，或在浮层中展开内容。
- **显示结果摘要**：控制任务结果摘要是否出现在通知中。
- **仅推送其他会话**：前台正在查看且空闲的会话不提示。
- **任务完成音效**：关闭（默认）、轻柔或清晰；可试听和即时关闭。
- **位置、主题、语言、自动消失**：调整应用内提示外观和时长。
- **通知呈现方式**：应用内类别可选旧版卡片 / 提升窗口助手；实际行为和动作支持因平台而异，与系统通知通道分开。
- **通知历史**：查看、重播或清空近期通知。静态桌面版最多在本地保留 200 条；动态插件版的历史只存在于内存中。

## 故障排查

### 没有系统横幅

- 确认 **任务完成** 使用「系统通知」。
- 检查设置中的 **系统通知权限**，以及 Windows 通知 / macOS 通知、专注助手或勿扰模式。
- 测试时保持 DSH 运行。系统可能隐藏横幅，但仍把通知留在通知中心。
- 权限被拒或系统投递失败时，检查是否出现应用内回退提示。

### 通知没有结果摘要

- 确认已开启 **显示结果摘要**。
- 只有最新用户回合存在可用的助手文本时才显示摘要；推理内容、工具结果和旧回合答案会被排除。
- 横幅只显示短预览；完整结果需打开会话查看。

### 点击系统通知没有打开会话

- 使用包含系统通知会话跳转功能的构建，并按宿主结果刷新或重启。
- 测试时保持 DSH 在后台运行；最小化或关闭主窗口后驻留托盘均可。完全退出应用不在恢复范围内。
- 更新生效并完成宿主要求的刷新或重启后，分别在最小化、驻留托盘状态下，用新产生的真实任务通知验证窗口恢复和来源会话跳转。
- 若跳转失败，设置页会显示失败状态；可从应用内提示或历史再次进入来源会话。
- 使用真实任务通知验证。测试按钮只携带发送时选中的会话，不验证真实任务摘要。

### 设置页可见，但没有通知

- 检查安装或更新后的宿主激活结果；按提示刷新页面或重启。
- 检查 **Host 连接状态**。若 Host 未连接，查看 DSH 日志和客户端控制台中的 `[dsh-task-toast]` / `[task-toast]` 错误。

## 卸载

- **DSH 桌面应用**：在 **插件 → 已安装插件** 中卸载。
- **Web profile**：

  ```sh
  dsh plugin --profile web remove dsh-task-toast
  ```

## 开发

需要 Node.js 18 或更高版本。构建不需要额外安装依赖。

```sh
npm run build       # 构建静态包和动态包
npm test            # 构建并运行通知、会话及客户端回归
node tests/stress-host.mjs
```

静态发行产物位于 `lib/`，动态备用产物位于 `dynamic/`。源码变更后要重建对应产物。开发时不要直接修改 DSH profile 中的已安装文件。
